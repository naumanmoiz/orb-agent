# Preparing switches for snmp_discovery

What a switch needs so `snmp_discovery` (standalone, or generated by the NetBox
prefix sync) can read it. Covers Cisco IOS-XE, Dell OS10 and SONiC.

Use **SNMPv3 authPriv with SHA + AES-128** everywhere. It is the one
combination every platform below and snmp-discovery agree on:

| Agent setting | Value | Why |
|---|---|---|
| `auth_protocol` | `SHA` | SHA-2 variants are not configurable on every platform's v3 user. |
| `priv_protocol` | `AES` (128) | Cisco's AES-256 uses Reeder key extension (`AES256C` in the agent), others use Blumenthal (`AES256`); AES-128 avoids picking wrong. |

Restrict SNMP to the agent's source address with an ACL, and expose a
read-only view instead of the whole tree.

## What snmp-discovery reads

The view has to include these subtrees; anything outside them is never read.

| OID | MIB | Gives |
|---|---|---|
| `1.3.6.1.2.1` | mib-2 (system, IF-MIB, IP-MIB, BRIDGE/Q-BRIDGE, ENTITY-MIB, IPv6, MPLS-L3VPN) | device, interfaces, MACs, IPs, VLANs, modules, VRFs |
| `1.3.6.1.3.118` | MPLS-VPN draft | VRFs on older IOS |
| `1.3.6.1.4.1.9.9.46`, `.9.9.68`, `.9.9.711` | CISCO-VTP, CISCO-VLAN-MEMBERSHIP, CISCO-VRF | Cisco VLANs, access VLANs, VRFs |

## Cisco IOS-XE (Catalyst 9k / ISR / CSR)

```
ip access-list standard ORB-SNMP
 permit host <AGENT_IP>
 deny   any log
!
snmp-server view ORB-RO mib-2 included
snmp-server view ORB-RO 1.3.6.1.3.118 included
snmp-server view ORB-RO 1.3.6.1.4.1.9.9.46 included
snmp-server view ORB-RO 1.3.6.1.4.1.9.9.68 included
snmp-server view ORB-RO 1.3.6.1.4.1.9.9.711 included
!
snmp-server group ORB-GRP v3 priv read ORB-RO access ORB-SNMP
snmp-server user <SNMP_USER> ORB-GRP v3 auth sha <AUTH_PASS> priv aes 128 <PRIV_PASS> access ORB-SNMP
!
snmp ifmib ifindex persist
snmp-server location <site name as in NetBox>
snmp-server contact <team>
```

Replace `access ORB-SNMP` with `access ORB-SNMP`. Notes:

- `snmp-server user` is not shown in the running config. Check it with
  `show snmp user`.
- `snmp ifmib ifindex persist` keeps ifIndex stable across reloads, so
  interfaces keep their identity between scans.
- When polled through the management port (`Mgmt-vrf`), SNMP answers there
  without extra commands on recent IOS-XE. If the probe times out, check
  `show snmp` counters and the ACL hit counts.
- SNMPv2c fallback, for a lab only:
  `snmp-server community <COMMUNITY> view ORB-RO RO ORB-SNMP`

Check from the agent host:

```
snmpget -v3 -l authPriv -u <SNMP_USER> -a SHA -A <AUTH_PASS> -x AES -X <PRIV_PASS> <SWITCH> sysDescr.0 sysObjectID.0
```

## Dell OS10 (S/Z/N series)

```
ip access-list ORB-SNMP
 seq 10 permit udp host <AGENT_IP> any eq snmp
 seq 20 deny udp any any eq snmp
!
snmp-server view ORB-RO 1.3.6.1.2.1 included
snmp-server view ORB-RO 1.3.6.1.4.1.674 included
snmp-server group ORB-GRP 3 priv read ORB-RO
snmp-server user <SNMP_USER> ORB-GRP 3 auth sha <AUTH_PASS> priv aes <PRIV_PASS>
!
snmp-server location "<site name as in NetBox>"
snmp-server contact "<team>"
! Only when the agent reaches the switch through the management port:
snmp-server vrf management
```

Apply the ACL to the control plane (`control-plane` → `ip access-group ORB-SNMP in`),
or to the management interface, according to your platform's guide. OS10
reports enterprise 674 (Dell). snmp-discovery ships `dellemc-os10.yaml` and
`f10.yaml` lookups, so the manufacturer and model are resolved.

## SONiC (community, Edgecore, Dell Enterprise SONiC)

From the Linux shell (`admin`). These Click commands write CONFIG_DB and work on
Enterprise SONiC too:

```
sudo config snmp user add <SNMP_USER> priv RO SHA <AUTH_PASS> AES <PRIV_PASS>
sudo config snmp location add "<site name as in NetBox>"
sudo config snmp contact add <team> <email>
# Agent listen address; use -v mgmt when reached through eth0 in the mgmt VRF:
sudo config snmpagentaddress add <SWITCH_MGMT_IP> -v mgmt
sudo config save -y
```

Restrict the source with a control-plane ACL (CONFIG_DB):

```json
{
  "ACL_TABLE": {
    "ORB_SNMP": { "type": "CTRLPLANE", "services": ["SNMP"], "stage": "ingress",
                  "policy_desc": "SNMP from orb-agent only" }
  },
  "ACL_RULE": {
    "ORB_SNMP|RULE_1":  { "PRIORITY": "9999", "PACKET_ACTION": "ACCEPT", "SRC_IP": "<AGENT_IP>/32" },
    "ORB_SNMP|DEFAULT": { "PRIORITY": "1",    "PACKET_ACTION": "DROP",   "ETHER_TYPE": "2048" }
  }
}
```

`sudo config load orb-snmp-acl.json -y && sudo config save -y`. On Dell
Enterprise SONiC the Klish `sonic-cli` has equivalent `snmp-server` commands,
but the syntax differs between releases. Check it on your release.

**Known gaps for SONiC. Test these on one switch before rolling out:**

1. **Manufacturer and model.** Community SONiC answers sysObjectID with net-snmp's
   `1.3.6.1.4.1.8072.3.2.10`, which maps to manufacturer `netsnmp` and no model.
   Fix it per switch with a lookup extension (`config.lookup_extensions_dir`),
   or set `defaults` for the platform. Dell Enterprise SONiC may report 674;
   check `sysObjectID.0` first.
2. **VLANs.** SONiC's agent serves Q-BRIDGE FDB entries, but the VLAN
   static/current tables are partial on some releases. Walk
   `1.3.6.1.2.1.17.7.1.4` to see what you get.
3. **IP addresses.** These come from net-snmp's IP-MIB over the kernel netdevs
   (`Ethernet0`, `Vlan100`, `Loopback0`), so they should be complete. Check
   `1.3.6.1.2.1.4.34` (ipAddressTable).

## Agent side

In the NetBox prefix sync config (`orb.config_manager.sources.netbox.snmp_discovery`):

```yaml
snmp_discovery:
  enabled: true
  schedule: "15 */6 * * *"
  authentication:
    protocol_version: SNMPv3
    security_level: authPriv
    username: ${SNMP_USER}
    auth_protocol: SHA
    auth_passphrase: ${SNMP_AUTH_PASS}
    priv_protocol: AES
    priv_passphrase: ${SNMP_PRIV_PASS}
  config:
    timeout: 300      # per-device walk budget in seconds; must exceed snmp_timeout
    snmp_timeout: 10
    retries: 2
```

`${VAR}` values are resolved by snmp-discovery from the agent container's
environment (`--env-file`). They are never written to the generated policies
file. If a variable is unset, the policy is refused with `failed to resolve
community` (or `username`, and so on).

`config.timeout` is in **seconds** and bounds one device's whole walk. It must be
greater than `snmp_timeout` (default 5). A value like `timeout: 5` makes
snmp-discovery reject every policy. `netbox-render` now reports this before
anything is deployed.

### Hand-written policies: always give the VRF's RD

Prefix-sync policies take the VRF from NetBox. A hand-written `snmp_discovery`
policy must name the VRF in full, under **both** `ip_address` and `prefix`.
With the name alone, the plugin cannot match a VRF that has an RD, and it
creates a second VRF with the same name and no RD:

```yaml
defaults:
  ip_address:
    vrf: {name: VRF-A, rd: "65000:100", tenant: Tenant A, tenant_group: Group A}
  prefix:
    vrf: {name: VRF-A, rd: "65000:100", tenant: Tenant A, tenant_group: Group A}
```
